# PXAX AI Прогнозы — Telegram Mini App (v0.9)

Мини-приложение для Telegram: ежедневные прогнозы на спорт от ИИ для подписчиков.

⚠️ **Во всех экранах присутствует дисклеймер:** прогнозы генерирует ИИ, вероятность не 100%, ставки — риск, 18+. Валюта личного трекера ставок — условные единицы: не деньги, не платёжное средство и не имеют никакой реальной ценности.

## Архитектура

- `index.html` — всё приложение одним файлом (без сборки): UI, свайп-колоды, пейвол, личный трекер ставок
- `scripts/generate-predictions.mjs` — генератор прогнозов по данным ESPN (без ключей): таблицы лиг, линии, xG-форма (Understat), травмы (ESPN). Пишет **два** файла: публичный `data/predictions.json` (только бесплатные прогнозы) и приватный `data/pro-feed.json` (VIP, в `.gitignore`)
- `scripts/publish-pro.mjs` — заливает VIP-фид в хранилище воркера админ-роутом; без настроенных секретов тихо пропускается
- `scripts/resolve-results.mjs` — резолвер: матчи последних 72 ч сверяются по id с реальными результатами ESPN (несыгранные возвращаются на следующий проход, отменённые — push) + калибровка; VIP-прогнозы берёт из воркера, предсезонку помечает и исключает из статистики
- `scripts/model.mjs` — общие функции модели: распределение счёта, xG-бленд, выбор рынка (`selectionScore`) и калибровка вероятностей (`calibrateProbability`, `homeAdvFromTotals`). Их же использует бэктест — иначе проверялась бы не та модель, что продаётся
- `test/model.test.mjs` — офлайн-тесты модели (выбор рынка, калибровка, домашний фактор), гоняются в CI без сети
- `scripts/check-public-feed.mjs` — страж пейвола: падает, если в публичных `data/*.json` появился платный сигнал PRO (`value`/`edge`/`impliedProb` или «перевес модели» в note); гоняется в CI до коммита данных
- `scripts/backtest.mjs` — бэктест модели по завершённым матчам за 90 дней (без заглядывания: только форма до матча + средний тотал лиги). Раньше он ранжировал рынки строго по вероятности, а генератор — строго по edge, то есть проверялась другая модель; теперь у обоих одна `selectionScore`, но линий в окне 90 дней нет, поэтому edge равен нулю и проходимость честно показывает чистую вероятностную модель → `data/backtest.json`
- `.github/workflows/predict.yml` — раз в 2 часа: генерация → публикация VIP-фида в воркер → резолв → коммит `data/*.json`; `.github/workflows/backtest.yml` — бэктест ежедневно; `.github/workflows/deploy-payments.yml` — деплой воркера оплаты
- `worker/` — бэкенд подписки (Telegram Stars) на Cloudflare Worker: `/api/status`, `/api/pro`, `/api/trial`, `/api/invoice`, вебхук Telegram, админ-роуты; D1 как основное хранилище (см. `worker/README.md`)
- `server/` — прежний Node-бэкенд через cloudflared-туннель; оставлен как запасной, для продакшена не используется
- `data/predictions.json` — бесплатные прогнозы на сегодня (+ только счётчики `proCount`/`botdLegs`), `data/results.json` — накопленная история, `data/backtest.json` — ежедневный бэктест модели, `data/calibration.json` — Brier-калибровка, `data/archive/` — по дням

Фронтенд сначала показывает мок (локальное превью без хостинга), но как только `data/predictions.json` за сегодня доступен — переходит на реальные данные и честную статистику. Отменённые матчи считаются возвратом (push) и не портят проходимость.

## Модель

Всё считается из бесплатных данных ESPN + Understat, без API-ключей и без LLM-вызовов.

1. **Сила команд** — по таблицам лиги (голы за/против, очки): атака и оборона как множители к среднему лиги, с шринком при малой выборке. Если текущий сезон только начался (<3 матчей), берётся таблица прошлого сезона — она куда информативнее пустой.
2. **xG-форма (только футбол, топ-5 лиг)** — из Understat (`getLeagueData`): средние xG за/против за последние 5 *завершённых* матчей перед датой матча (без lookahead'а) корректируют ожидаемые голы на до ~10%. Если Understat недоступен или лига не покрывается — тихий fallback на гол-форму. К имени команды матчинг: точное → алиасы → префикс → срез клубных префиксов («AFC Bournemouth», «AS Roma»).
3. **Распределение** — распределение счёта для футбола и хоккея, нормальное приближение для NBA (очки — почти непрерывная величина). Из распределения получаются все рынки сразу: П1/Х/П2, тоталы (ТБ/ТМ), форы.
4. **Коэффициенты** — читаются реальные линии ESPN (moneyline/total), маржа снимается девигом. Модельная вероятность сравнивается с **честной** вероятностью линии.
5. **value** — если модель выше честной вероятности линии больше чем на **5%**, рынок помечается `value` и попадает в PRO как value-ставка (порог 5%: меньше — шум).
6. **Выбор рынка** — база это вероятность, перевес над линией лишь слегка её повышает (`selectionScore`, вес 0.25, добавка зажата ±0.5). Раньше рынок выбирался строго по максимуму edge, и карточку всегда забирал самый несогласный с линией рынок — а несогласие чаще всего и есть ошибка модели: в истории заходы с большим edge были хуже (нижняя половина 80%, верхняя 53%, крупнейшие «перевесы» +86%/+55%/+48% — мимо). FREE — самые надёжные прогнозы, PRO — ставки с перевесом; метка `value` осталась у PRO, но выбирать по ней рынок больше нельзя.
7. **Травмы** — league-level endpoint ESPN (`.../injuries`): до 3 injured-игроков на команду со статусом (Out/Doubtful/Probable/…) добавляются в `note` матча.
8. **Калибровка** — резолвер считает Brier и корзины «предсказано → фактически» по накопленной истории, а генератор **применяет** поправку: по семействам рынков (исход / двойной шанс / тотал), с долей заходов и шринком Лапласа, зажатой в ±6 пунктов от исходной вероятности. Раньше файл только показывался в интерфейсе — а модель продолжала недооценивать себя на 6–10 пунктов (предсказано 55%, фактически 65%).
9. **Домашний фактор по лигам** — считается из фактических голов лиги (`homeAdvFromTotals`), а не одной константой 1.15: в Аргентине и Бразилии преимущество поля своё. Пока по лиге меньше 40 решённых матчей, берётся общая константа — лучше она, чем шум по трём играм.

## Новые фичи v0.9.1

- ⚖️ **Честный вердикт «VIP vs Базовый» только на достаточной выборке.** Вердикт «VIP-прогнозы заходят чаще — подписка может окупиться» строился по разнице округлённых процентов без оглядки на размер выборки. На реальных данных это давало «+9 п.п., окупается» из **4 из 5**: 95% интервал для 4/5 — примерно 38–96%, разница целиком внутри случайного разброса (z ≈ 0.42). Теперь при выборке меньше `CONFIG.MIN_CMP_N` (20 решённых у каждого вида) выводится нейтральный текст «нужно хотя бы 20 — сейчас Базовый N, VIP M». Порог тот же, что у калибровки.
- 🔎 **Предсезонные матчи больше не исчезают из статистики молча.** Их по-прежнему не берём в проходимость (модель считает силу команд по регулярке), но теперь показываем отдельной плашкой: «Ещё N предсезонных матчей не учтены выше». Раньше из 12 отданных подписчику PRO-прогнозов 7 были предсезонкой NBA и молча выпадали из VIP-статистики — 80% считались по 5 матчам вместо 12 (по всем отданным вышло бы 7 из 12 = 58%).
- 🧮 **Окно истории согласовано с цифрами.** Подпись над списком была «7 дней» хардкодом, а верхние счётчики считались за `CONFIG.STAT_DAYS` (14) — при накоплении данных они бы разошлись. Теперь и список, и подпись берут `STAT_DAYS` из конфига.

## Новые фичи v0.9

- 🔐 **Настоящий пейвол: VIP-контент больше не лежит в открытом файле.** Раньше все PRO-прогнозы были в публичном `data/predictions.json` вместе с флагом `tier` — их скачивал кто угодно curl-ом, минуя оплату. Теперь генератор пишет VIP отдельным файлом (`data/pro-feed.json`, в `.gitignore`), CI заливает его в хранилище воркера, а приложение получает прогнозы через `GET /api/pro` по подписанному `initData` и только при активной подписке. В публичном файле остались лишь счётчики (`proCount`, `botdLegs`) — чтобы пейвол мог честно написать «сегодня 5 сигналов», не раскрывая их.
- 🧪 **Предсезонные матчи исключены из модели и статистики.** ESPN помечает preseason (`season.type = 1`): NBA в октябре играет ротацией, а сила команд считалась по таблицам регулярки — отсюда были «перевесы» в +66% на тоталах и 4 из 5 PRO-ставок дня из NBA. Генератор такие матчи не берёт, резолвер помечает их `preseason: true` и не пускает ни в проходимость, ни в Brier, ни в список истории. Побочный эффект честности: проходимость выросла с 61% до 75%, потому что из выборки ушли 15 preseason-строк.
- 💾 **Платежи переехали с KV на D1.** На free-плане у KV 1000 записей в сутки **на аккаунт**, и этот лимит выбирал соседний проект (AI-компаньон пишет состояние и память: по аналитике Cloudflare вышло 1201 запись при лимите 1000). Оплата падала с «KV put() limit exceeded for the day» — для приёма денег это недопустимо. Пользователи и VIP-фид теперь в D1 (лимит 100 000 строк в сутки), KV остался запасным путём.
- 🐛 **Статистика на вкладке «Статистика» показывала 0/0/0.** Фильтр «Все» передавался в подсчёт как вид прогноза (`statFilter = 'all'`), и условие `r.kind !== 'all'` отбрасывало все строки. Теперь «Все» — это отсутствие фильтра.

## Новые фичи v0.8

- 💳 **Оплата Stars напрямую в вебвью.** Счёт открывается через `openInvoice` (бот присылает ссылку `createInvoiceLink`), не нужно искать сообщение в чате. Цена, срок и длительность пробы берутся из ответа сервера — во фронтенде нет ни одного захардкоженного числа плана.
- 🔒 **Пейвол без утечки VIP-прогноза.** Заблокированная карточка не рендерит рынок, кэф, перевес и разбор вовсе; ноги «Ставки дня» без подписки тоже не выводятся (см. раздел ниже).
- 🎞️ **Переходы между вкладками без «проявления» прошлого экрана.** Анимация входа перестала быть полупрозрачной, поэтому `backdrop-filter` на шапке и таббаре больше не подмешивает в фон предыдущий кадр.
- ☁️ **Бэкенд оплаты на Cloudflare Worker** (`worker/`): постоянный адрес вместо cloudflared-туннеля, идемпотентные платежи по `telegram_payment_charge_id`, 16 автотестов, деплой из CI.

## Новые фичи v0.7

- 🧾 **Личный трекер ставок + ROI.** На карточке — кнопка «Я поставил» (localStorage, без сервера). Как только матч появляется в `results.json`, P/L считается автоматически: win = (kэф−1)·stake, miss = −stake, push = 0. В профиле: P/L, ROI, проходимость, текущий стрик, размер ставки (усл. ед.), последние 12 ставок. Валюта трекера — исключительно условная: не деньги и не имеет никакой реальной ценности.
- 💎 **«Ставка дня» (PRO-экспресс).** Генератор собирает экспресс из 2–3 сигналов: только уверенность ≥70% у каждой ноги, приоритет value-рынков. Показывается в PRO-вкладке с суммарным кэфом и совместной вероятностью модели; без PRO — за замком.
- 📊 **xG-форма** в футбольных прогнозах (top-5 лиг) — см. п.2.
- ⚡ **Value-порог 5%** вместо 3% — fewer false value-badges.
- 🏥 **Травмы в разборе матча** (ESPN injuries) — см. п.6.
- 📡 **Честный статус «собираем данные».** Пока живых завершённых матчей меньше 20 — плашка с количеством сыгранных и явной пометкой, что цифры недостоверны; при нуле — ориентир на бэктест модели.

## Пейвол

Две независимые вещи, обе нужны, чтобы VIP был платным по-настоящему.

**Данные.** PRO-прогнозы в публичный репозиторий не попадают: генератор пишет их в
`data/pro-feed.json` (в `.gitignore`), CI заливает фид в хранилище воркера, приложение
получает его через `GET /api/pro` с подписанным `initData` — и только при активной
подписке. Без неё роут отвечает `403 no_subscription`, не отдавая ни одного прогноза.
В `data/predictions.json` остаются только бесплатные прогнозы и счётчики `proCount` и
`botdLegs`, чтобы пейвол мог написать «сегодня 5 сигналов Pro-ИИ», не раскрывая их.

Платный сигнал — это не только сам прогноз, но и сравнение модели с линией. Вырезать
одним `stripTier` только поле `tier` было мало: в публичный файл уходили `value`, `edge`,
`impliedProb`, `edge` внутри `markets`, да ещё в `note` прямая фраза «перевес модели
+N%» — то есть ровно то, за что берут Stars, скачивалось curl-ом, а на бесплатных
карточках рисовался бейдж VALUE. Теперь генератор собирает публичную запись через
`publicFree()` (без этих полей и без сравнения с линией), резолвер не пишет
`edge`/`value` в публичный `results.json`, а `scripts/check-public-feed.mjs` гоняется
в CI после генерации и до коммита: если платный сигнал вернулся в `predictions.json`,
архивы или `results.json`, пайплайн падает и ничего не публикуется. Старые архивы и
`results.json` вычищены от `tier`/`value`/`edge`.

**Интерфейс.** Заблокированная карточка не рендерит рынок, коэффициент, перевес и разбор —
раньше они лежали в DOM и читались в кадре до применения CSS-фильтра. Ноги «Ставки дня» и
её суммарный кэф без подписки тоже не выводятся. Анимация перехода между вкладками
перестала быть полупрозрачной: липкая шапка и таббар с `backdrop-filter` больше не
подмешивают в фон кадр предыдущей вкладки, из-за чего под блюром на миг «проявлялись»
VIP-ставки.

## Бэкенд подписки

Продакшен — Cloudflare Worker в `worker/`: https://pxaxbet-payments.xstayis.workers.dev

1. Хранилище — D1 `pxaxbyte` (таблицы `pxaxbet_users`, `pxaxbet_pro`), KV `pxaxbet-users` оставлен запасным
2. Секреты: `wrangler secret put BOT_TOKEN`, `WEBHOOK_SECRET`, `ADMIN_KEY`
3. `wrangler deploy`, затем один раз `setWebhook` на `https://<воркер>/tg/<WEBHOOK_SECRET>`
4. Цена и сроки — в `worker/wrangler.toml` → `[vars]` (`STARS_PRICE`, `PRO_DAYS`, `TRIAL_DAYS`); фронтенд берёт их из `/api/status` и ничего не хардкодит

Тесты: `node worker/test/payments.test.mjs` (16 проверок, включая работу на D1).
Подробности — в `worker/README.md`.

Прежний Node-бэкенд: `server/config.json` с `TOKEN` → `node server/server.js` (long-polling, свой сервер + туннель).

Нужно понять, устаревшая это линия ESPN или неверный парсинг `overUnder`. Сейчас такие рынки вычищает фильтр preseason, но в регулярном сезоне вопрос вернётся.
3. **LLM-разбор**: заменить текстовые `note` на запрос к LLM с пост-валидацией по числам (сейчас разбор строится шаблонно из чисел модели).
4. **Уведомления ботом**: «прогнозы на сегодня готовы», «твой прогноз зашёл», напоминание об окончании подписки.
5. **xG на другие лиги** (MLS/Лига MX/Бразилия) — когда Understat их даст; сейчас fallback на гол-форму.
6. **Экспорт личного ROI** (CSV/скриншот) для отмеченных ставок.
7. **Лимиты Cloudflare под контролем.** Токен, которым деплоится воркер, умеет Workers и KV, но не создаёт базы D1 (для этого нужен `D1:Edit`) — сейчас воркер использует существующую базу `pxaxbyte` совместно с AI-компаньоном. Если проекты начнут мешать друг другу, стоит завести отдельную D1 и расширить права токена.

## Деплой

1. Разместить репозиторий на HTTPS-хостинге (сейчас — GitHub Pages: `https://xstayis-hue.github.io/pxax-predict/`)
2. В @BotFather: `/newapp` → указать URL мини-аппа (или задать `MINIAPP_URL` в `worker/wrangler.toml`)
3. Задеплоить воркер оплаты (`worker/README.md`) и прописать его адрес в `CONFIG.API_BASE` командой `node worker/link.mjs https://<воркер>`
4. Один раз привязать вебхук Telegram на `https://<воркер>/tg/<WEBHOOK_SECRET>` (команда в `worker/README.md`)
